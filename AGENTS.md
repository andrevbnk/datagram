# Datagram — принципы работы агента

Этот файл описывает, как агент (Hermes) должен работать над проектом **Datagram** в этом топике. Он авто-подгружается, когда рабочая директория — эта папка.

## Проект

- **Репозиторий:** https://github.com/andrevbnk/datagram
- **Локальный клон (рабочая папка топика):** `C:\Users\admin\Desktop\TG\datagram-main`
- **Описание:** datagram tg groups (Telegram-группы).

## Рабочая папка топика

Все файлы, которые агент создаёт в процессе работы, сохраняются в этой папке (корень репозитория). Заметки и договорённости — в подпапке `notes/`.

## Git-процесс (обязательный)

Когда пользователь просит что-то сделать (изменить код, добавить функциональность, поправить баг):

1. **Создать отдельную ветку** от `develop` (по умолчанию). Имя ветки — короткое и осмысленное, например `feature/<описание>` или `fix/<описание>`.
2. **Внести изменения** в этой ветке.
3. **Закоммитить** с понятным сообщением.
4. **Запушить** ветку в origin.
5. **Создать pull request** на GitHub в ветку `develop` (по умолчанию).

Базовые ветки:
- `develop` — ветка разработки, куда мержатся PR (по умолчанию).
- `main` — стабильная ветка.

Если пользователь явно не указал иное, PR создаётся в `develop`.

## Заметки и договорённости

Важные факты, решения и договорённости фиксируются в markdown-файлах в `notes/`. Каждая заметка — отдельный файл с понятным именем (например, `notes/2026-09-10-workflow.md`).

## GitHub-авторизация

Токен хранится в `GITHUB_TOKEN` (в `~/.hermes/.env`). Git настроен на push через credential helper (`~/.git-credentials`). Для создания PR используется GitHub REST API (`POST /repos/andrevbnk/datagram/pulls`) с этим токеном.

## Правила

- Не коммитить секреты, токены, ключи.
- Перед объявлением задачи выполненной — проверить, что push и PR реально созданы (прочитать ответ API).
- Не работать напрямую в `develop` или `main` — только через feature-ветки.
